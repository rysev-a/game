# Механика игры

Как устроены квесты, диалоги, инвентарь, крафт, приборы, бои и головоломки, чтобы **новый квест был
файлом с данными, а не новым кодом**. Сюжет, персонажи и список квестов — в [docs/story](../story/README.md);
здесь — как это всё будет работать в коде.

## Главная идея

Сейчас каждый разговор и каждая сцена — отдельный код: `rootDialogue` в `src/player/talk.js` собирает варианты
через `if`, сцена у реки — 240 строк в `src/locations/bridge/incident.js`. Для 43 квестов так не получится.

Поэтому игра делится на два слоя:

1. **Механики (код, пишется один раз).** Небольшое число универсальных систем: состояние истории, условия,
   действия, квесты, диалоги, инвентарь со стопками, рецепты и заказы, станции, приборы, бой, головоломки.
   Каждая система знает только свои *виды* вещей: «головоломка-сборка», «способность-невидимость»,
   «прибор-зрение».
2. **Содержание (данные).** Квесты, реплики, предметы, рецепты, существа, конкретные головоломки. Это объекты
   из литералов: строки, числа, списки. Они ссылаются друг на друга по `id` и пользуются общим языком
   [условий и действий](core.md#условия).

Новый квест — это новый файл в `src/content/quests/`: шаги, условия, реплики и награды. Код пишется, только
когда нужна **новая механика** (новый вид головоломки, новая способность босса), и тогда она сразу доступна
всем следующим квестам.

## Принципы

- **Данные — только литералы.** Никаких функций в файлах содержания. Условие — строка вроде
  `'has:copper>=2'`, действие — объект вроде `{ give: 'analyzer' }`. Так содержание можно проверить
  автоматически, а потом при желании перенести в JSON или редактор.
- **Один квест — один файл.** В файле квеста лежат и его шаги, и реплики персонажей, которые нужны только
  для этого квеста, и его головоломки. Общие реплики персонажа — в файле персонажа.
- **Аварийный люк.** Если что-то уникальное (воспоминание с плотом на реке, взрыв цеха) не ложится в данные,
  его пишут один раз как именованный сценарий `defineScript('raft_flashback', ...)` и вызывают из данных
  действием `{ script: 'raft_flashback' }`. Это исключение, а не правило.
- **Без сборщика.** Игра — классические `<script>` без бандлера, и ее можно открыть через `file://`
  (тогда `fetch` не работает, см. `game.json` в `src/engine/clock.js`). Поэтому файлы содержания — это `.js`,
  которые вызывают `defineQuest({...})` и т. п., а не `.json` через `fetch`. Подключаются после механик.
- **Всё сохраняется одним снимком.** Состояние истории — один объект `story`, он целиком попадает в
  `captureGame/applyGame` (`src/player/saves.js`).
- **Существующее не ломаем.** Толкание машины, канистра соседа, заправка, сцена у реки продолжают работать;
  их переносят на новые механики постепенно, когда это упрощает код.

## Папки

```
src/
  mechanics/                  код механик (подключается после src/player и src/locations, до src/world/world.js)
    story.js                  состояние истории, реестр define*, события
    conditions.js             язык условий
    effects.js                язык действий
    places.js                 именованные места (definePlace)
    quests.js                 квесты, шаги, маркер на миникарте
    journal.js                журнал (J): задания, выводы, люди, чертежи
    characters.js             именованные персонажи: появление, расписание, диалог
    dialogs.js                диалоги из данных поверх src/engine/dialogue.js
    crafting.js               рецепты, мастера, заказы со временем
    stations.js               станции в мире (верстак, генератор, серверная стойка)
    spots.js                  точки в мире: тайники, улики, предметы на земле
    devices.js                приборы героя и их режимы
    combat/                   бой: герой, существа, способности, стычки
    puzzles/                  оверлей головоломок и виды (sequence.js, assembly.js, ...)
  content/                    ДАННЫЕ (здесь живет почти вся новая работа)
    items.js                  предметы
    characters/               по файлу на персонажа: кто, где, общие реплики
    quests/                   по файлу на квест: 1-01-morning.js, 2-08-analyzer.js, ...
    recipes.js                рецепты эликсира и приборов
    devices.js                приборы героя
    creatures.js              существа из лаборатории и боссы
    puzzles/                  общие головоломки (если не лежат в файле квеста)
assets/
  puzzles/                    картинки для 2D-головоломок
```

## Как добавить квест (чек-лист)

1. Создать `src/content/quests/2-08-analyzer.js` с `defineQuest({...})` (формат —
   [quests-and-dialogs.md](quests-and-dialogs.md#квест)).
2. Если нужны новые вещи — добавить их в `src/content/items.js` и пиксельный значок в `PIXEL_ART`
   (`src/player/icons.js`).
3. Если нужен рецепт или заказ у мастера — запись в `src/content/recipes.js`.
4. Если нужна головоломка или бой — описать их в том же файле квеста (виды уже есть в механиках).
5. Подключить файл в `index.html` в блоке содержания.
6. Открыть игру с `?dev`: проверка содержания напишет в консоль, если какой-то `id` не найден, а
   `story.dev.start('2.08')` сразу поставит квест (см. [core.md](core.md#отладка)).

Код пишется только если квесту нужна механика, которой еще нет.

## Порядок внедрения

Каждый пункт — отдельный PR. После каждого игра работает, и на новую механику сразу переносится
что-то настоящее из актов 1–2, чтобы проверить ее в деле.

| # | Что | Проверяем на |
| --- | --- | --- |
| 1 | Ядро: `story`, условия, действия, события, места, реестр, сохранения v2, `?dev` | — |
| 2 | Инвентарь со стопками, карточка предмета, «использовать» | канистра, ключи |
| 3 | Персонажи и диалоги из данных, темы, «отдать / показать» | Николай Палыч, сосед, полицейский |
| 4 | Квесты и журнал (J), маркер на миникарте | 1.01–1.03 |
| 5 | Рецепты, мастера, заказы со временем, станции | 2.04, 2.08, сервер Олега |
| 6 | Оверлей головоломок и первые виды: `sequence`, `choice`, `assembly`, `jigsaw` | 2.05, 2.01, 1.05 |
| 7 | Приборы героя: режимы и заряды | анализатор, очки |
| 8 | Бой: герой, существа, способности, стычки, браслет | первые существа, Тень |

Остальные виды головоломок и способности боссов добавляются по мере того, как до них доходят квесты.
