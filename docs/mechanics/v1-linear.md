# Первая версия: абсолютно линейная игра

> Сначала делаем самую простую игру от начала до конца: герой идет по цепочке подсказок, побеждает главного
> злодея и спасает девушку. Ни побочных квестов, ни развилок. Всё остальное растет вокруг этой готовой линии.

Язык данных (условия, действия, события) — в [core.md](core.md), квесты и диалоги — в
[quests-and-dialogs.md](quests-and-dialogs.md). Здесь — что из них входит в первую версию и какие квесты
собирают тонкий срез сюжета.

## Что входит, что нет

| Входит в v1 | Не входит (позже) |
| --- | --- |
| Одна сюжетная цепочка, квесты идут строго по порядку | Побочные квесты |
| Шаги внутри квеста тоже строго по порядку | Развилки, выбор, разные исходы |
| Каждый квест — один файл с данными, кода нет | Игра за другого персонажа (например за Веру) |
| Подсказки: каждый квест открывает следующую | Таймеры и поражение вертолетом (после первых трех квестов) |
| Бой, головоломки, вождение, договоры с людьми, сборка приборов | Шаблоны побочных квестов, `roles`, `world` |
| Поле `meta` у любой записи (движок его не читает) | Типизация `meta` |

Если механика нужна квесту, ее добавляют в тот момент, когда до этого квеста дошла очередь, и не раньше.

### Что нужно построить под эту цепочку

Порядок внедрения, в котором появляется новое:

1. **Ядро** (`story`, `check()`, `run()`, реестр, сохранения v2, журнал, маркер на карте) и квест 1.03 на нем.
   Сцена у реки (`incident.js`) подключается как есть: ее завершение — событие, которое отмечает шаг.
2. **Диалоги из данных** (`defineDialog`, `topics`): квесты 1–2.
3. **Крафт и головоломки** (`defineRecipe`, `definePuzzle`, вид «порядок» и «ритм»): квесты 3–4.
4. **Стычки**: бой и вождение через общий `encounter`: квест 5. Босс и ловушка как взаимодействие с предметом.
5. **Приборы и сервер** (`defineDevice`): квесты 4, 6, 8.
6. **Зал капсул и финал**: квесты 7–9. Здесь же добавляются таймеры и вертолет, если они понадобятся (например
   ночной пропуск 4.08).

После каждого пункта игра проходится от начала до последнего готового квеста. Недоделанные квесты в игру не
подключаются.

## Формат квеста в v1

Файл `src/content/quests/<номер>-<имя>.js`, один вызов `defineQuest`. Функций внутри нет.

```js
defineQuest({
  id: '2.08',
  title: 'Анализатор',
  goal: 'Собрать анализатор тканей',        // короткая цель для журнала
  next: '2.11',                              // следующий квест цепочки
  steps: [                                   // идут строго по порядку
    { id: 'find_smith', text: 'Найти, кто сделает корпус', done: 'talked:mihalych' },
    { id: 'bring',      text: 'Привезти Михалычу чертеж и вибраниум', done: 'step:2.08.bring', marker: 'kamenka.forge' },
    { id: 'forge',      text: 'Помочь у станка', done: 'puzzle:2.08.bellows' },
    { id: 'pick',       text: 'Забрать анализатор', done: 'has:analyzer', marker: 'kamenka.forge' },
  ],
  topics: { mihalych: [ /* реплики этого квеста у других персонажей */ ] },
  nodes: { /* узлы диалога этого квеста */ },
  puzzles: { bellows: { kind: 'rhythm', /* ... */ } },
  onDone: [{ reveal: 'Ф17' }, { start: '2.11' }],
  meta: {},                                  // что угодно, движок не читает
});
```

Поля v1: `id`, `title`, `goal`, `next`, `steps` (с `id`, `text`, `done`, `marker`, `hint`), `topics`, `nodes`,
`puzzles`, `encounters`, `interactions`, `onDone`, `meta`. Все остальное из
[quests-and-dialogs.md](quests-and-dialogs.md) (`requires`, `autoStart`, `order: 'any'`, `optional`, `fail`) в
v1 не нужно: порядок задает `next`.

### Поле `meta`

Есть у любой записи (`defineQuest`, `defineItem`, `defineCharacter`, …). Правила:

1. **Движок не читает `meta`** и не проверяет. Логики там нет: условия и действия живут только в настоящих полях.
2. Значения — любой JSON. В сохранения не попадает: это содержание, а не состояние.
3. Ключи с префиксом: `design.`, `balance.`, `ui.`, `author.`, `audio.`, `todo.`.
4. `checkContent()` печатает перепись ключей `meta` и сколько записей их используют.
5. Ключ, который встретился в 5 и более записях и нужен коду, повышается до настоящего поля (скриптом
   миграции).

## Подключение к игре (PR 1)

Квестовая система подключена **без правки старых файлов**: пока над репозиторием работают параллельно, в него только
добавлены новые файлы. Как это устроено:

- **Запуск.** В конце `index.html` стоит загрузчик `src/quests/load.js`. Он по очереди грузит файлы из `src/quests/manifest.js`: ядро (`src/core`),
  содержание (`src/content`), подключение (`src/quests/host.js`, `places.js`, `hooks.js`, `journal-ui.js`, `start.js`)
  Тесты в Node читают тот же список.
- **Тесты.** `npm test` — ядро на выдуманных данных (`tests/core.test.js`), настоящее содержание и сценарии
  прохождения (`tests/content.test.js`, сценарии в `tests/scenarios/`). Каждому квесту нужен сценарий с его id.
- **Обертки вместо правок.** `src/quests/hooks.js` оборачивает функции игры (они глобальные, вызовы идут по имени):

| Что | Где должно быть на самом деле |
| --- | --- |
| `captureGame` / `applyGame`: в слот пишется `story` (версия сохранения прежняя, слот без `story` начинает историю заново) | `src/player/saves.js` |
| `rootDialogue`, `personTitle`: разговор с Денисом берется из данных | `src/player/talk.js` |
| `spawnIncident`, `despawnIncident`, `updateIncident`, `updateOfficers`: Денис у ленты, осмотр тела, сцена живет, пока идет квест | `src/locations/bridge/incident.js` |
| `drawMapView`: метка текущего шага на миникарте и карте | `src/engine/minimap.js` |
| журнал помечает себя как `dialogueOpen` (пауза ввода, Esc закрывает окно, а не открывает настройки) | свой `journalOpen` в `escOverlayOpen`, `src/engine/mouse-look.js` |

- **Когда файлы можно будет править:** перенести каждую обертку по таблице на ее место. В `demo/index.html` квесты
  не подключены: ДЕМО проверяет механики, квесты в нем не нужны.

### Клик по человеку, двери и машине

Это механика платформы, она живет в общих файлах (`src/player/click-move.js`, настройка в `src/engine/settings.js`) и
работает и в игре, и в ДЕМО. Настройка «Клик по человеку, двери и машине» (вкладка «Управление», включена по умолчанию, `settings.clickInteract`):
клик по человеку — герой подходит и заговаривает; по двери здания — идет ко входу и входит (это уже делал
`click-move.js`); по машине — подходит и садится (закрытая или без ключей — сообщает причину, как по E). Правило одно
для всех трех: идем `clickDoorFrames` (2 секунды), не дошли — сразу оказываемся рядом, а игровое время уходит как на
оставшийся путь пешком. Ходьба по прямой, без обхода препятствий: уперлись — те же 2 секунды и перенос.
Выключили настройку — клик по людям и машинам просто ведет по земле, а дверь — к точке перед зданием.

### Взаимодействия: квест перехватывает E у станции

Станция здания с `id` (например `id: 'laptop'` у ноутбука Веры в `src/content/buildings/treehouse.js`) отдает E сначала
активному квесту: `interactions: [{ on: 'station:laptop', if: [...], do: [...] }]` в файле квеста
(`game.interact`, `src/core/game.js`). Если ничего не подошло, выполняется обычное действие станции. Так новый квест
не требует кода в зданиях: нужен только `id` у станции. Жилец с `charId` разговаривает по данным (`defineDialog`), а
`talk` остается запасным разговором.

### Головоломки

Головоломка — данные в файле квеста (`puzzles: { elixir: { kind, title, hint, pieces, answer, onSolve } }`), вид — код,
который пишется один раз (`Core.puzzleKinds`, `src/core/puzzles.js`). Сейчас есть вид `sequence`: выбрать части по порядку,
после `mistakesAllowed` ошибок выбранное сбрасывается. Вид `rhythm` (станок Михалыча, 2.08): бегунок ходит по полосе, нужно `beats`
верных нажатий подряд, когда он в зеленой зоне (`tolerance`). Ссылка `'2.05.elixir'`: открывает действие `{ puzzle: '2.05.elixir' }`,
решенность проверяет условие `puzzle:2.05.elixir`. Окно рисует `src/quests/puzzle-ui.js`, логика проверяется в Node без экрана
(в сценарии: `{ puzzle: '2.05.elixir', picks: [...] }`). Новый вид — запись в `Core.puzzleKinds` и, если нужен свой экран,
ветка в окне. Действие `{ elixir: 60 }` добавляет эликсир на шкалу героя.

### Таймеры

Таймер — данные квеста (`src/core/game.js`): `step.timer = { limit: '55m', warn: { '60%': [...] }, onExpire: [...], repeat }` у шага (стартует,
когда шаг становится текущим) или `quest.timer = { limit, start, until, ... }` у всего квеста (идет, пока `start` истинно, а `until` ложно).
Таймеры идут в реальных секундах (`limit: '55m'` — 55 секунд; часы таймеров `state.storyClock` стоят на паузе в разговоре и не зависят от игровых часов), на экране — обратный отсчет у значка телефона (`src/quests/timers-ui.js`);
в разговоре, журнале и головоломке время таймера стоит. Сработал — `onExpire`; с `repeat` таймер запускается заново, а действие
`{ rewind: '4.12.f1' }` возвращает квест к шагу (шаги, бои и головоломки квеста заново). Так сделаны погоня 2.12 (не успел доехать — на
старт, не успел забрать — люди в черном у входа) и бомба 4.12 (не успел — взрыв, подъем заново). Счетчик заноса `driftTime`
(`count:driftTime>=3`) копится, пока герой дрифтует за рулем: им квест заставляет объезжать заносом деревья, поваленные ночной бурей (спотам chase_b1…5 в `src/content/world.js` — ствол поперек полосы с корнями и кроной). Деньги — счетчик `money`
(`{ add: { money: -70 } }`, `count:money>=70`), прилавки — объекты мира с `interactions`.

### Телефон героя, звонок, бензин и жесткие таймеры

Журнал — это телефон героя (`src/quests/journal-ui.js`, J или значок рядом с инвентарем): главный экран с приложениями, статус-строка с игровыми часами. Всё, что герой знает о задании, он смотрит в нем.
Игра начинается со звонка: действие `{ call: { from: 'denis', dialog: '1.03.call' } }` (`src/core/effects.js`) включает входящий вызов (телефон трясется и звенит, ответить — кнопка, Enter, E или Пробел), а после ответа открывается разговор; пока звонит, игра на паузе, таймеры стоят.
Бак — данные: `{ fuel: 0.4 }` (доля), `{ fuel: 'river' }` — ровно столько бензина, чтобы хватило от дома до реки (длина трассы по `highwayLengthToRiver`, если дорога ее задала, иначе прямая × 1,15, плюс 4% запаса), условие `fuel:>=0.3`.
Так устроено начало: 1.03 — звонок Дениса, у моста «странные люди в черных очках», два черных фургона, таймер, бензина хватит ровно до реки; после осмотра тела Денис отправляет героя к бабушке Веры; бак не обнуляется (что осталось после дороги до реки, то и осталось), а если бензин действительно кончится, любого прохожего на трассе можно попросить подтолкнуть машину до заправки за мостом (`src/player/talk.js`).
Почти каждый шаг-дорога других квестов тоже ограничен по времени (`step.timer`: предупреждение на 60%, не успел — сообщение и возврат героя с машиной на место старта шага, `repeat`): 2.02, 2.05, 2.06, 2.08, 2.11, 2.13, 2.14, 3.04, 3.05, 4.09, 5.02, а погоня 2.12, гонка 3.05 и бомба 4.12 были такими с самого начала.
Шаги, где ждут (ночь, утро, вечер), и разговоры без дороги таймеров не имеют.

### Атрибуты вселенной: привычное появляется не сразу

Привычные для игры вещи — миникарта, инвентарь, сохранения, здоровье, телепорт — не даны с начала, а объясняются супер-предметами сюжета (ирония игры).
Условие каждого — вещь или флаг в состоянии story, код один раз спрашивает его (`src/quests/gates.js`, `questUnlocked`):

| Атрибут | Появляется, когда | Что было до этого |
|---|---|---|
| телефон героя (значок рядом с инвентарем, J) | герой взял телефон со столика в гостиной (1.03, шаг `phone`) | значка нет; телефон сразу звонит, звонок записывается |
| миникарта и таймер | сами, как только герой взял телефон (миникарта — карта телефона; в супер-окне про телефон они подробно расписаны) | миникарты и таймера нет |
| инвентарь (I) | бесконечный рюкзак из сундука в домике на дереве (1.06, предмет `backpack`) | панели инвентаря нет; ключи лежат в нижней ячейке |
| сохранения | супер-браслет Веры там же (1.06, устройство `bracelet`) | слотов нет; смерть — всё заново (первые два квеста) |
| здоровье и эликсир | прибор восстановления тканей, он оживает при варке первого эликсира (2.05, предмет `regen`) | полос нет, любая рана смертельна: загрузка последнего сохранения, без браслета — начало истории |
| телепорт по карте | артефакт возврата из сейфа Штерна (4.11, предмет `artifact`) | перемещения по карте нет, только дорога |

Ключи от машины лежат в нижней ячейке; их нужно «применить» на машину (нажать цифру ячейки и кликнуть по машине, флаг `carOpen`), иначе в первом квесте она заперта.
Корпус для браслета (3.04, флаг `braceletCased`) нужен для возврата во времени (вечерняя тренировка в 3.05).
Телефон — не просто инвентарь: приложения «Звонки» (история звонков, «Прослушать» показывает разговор диалогом; запись идет сама, пока герой говорит по телефону), «Сообщения», «Заметки» (выводы и знакомые),
«Задания» (текущие и выполненные), «Навигатор» (цель и расстояние, кнопка карты), «Таймер»; таймер квеста еще и висит значком у телефона. Строки цели на экране больше нет: если герой забыл, что делать, он открывает телефон.

### Пицца на время (2.15) и транспорт квеста

Подработка перед покупкой деталей для оружия: Геннадий («Тесто», во дворе у заправки) дает мотороллер и пять заказов, каждый заказ — шаг с таймером и своим местом (`pizza.c1`–`c5`).
Вовремя — 80 за заказ, всего с расчетом 500 (на них покупают детали в 2.13). Не успел — пицца остыла, герой возвращается на место прошлого заказа вместе с мотороллером (`{ teleport: { to, car: true } }`
телепортирует тот транспорт, на котором герой сидит, если он квестовый) и пробует еще раз.
Мотороллер — новый вид в `VEHICLE_KINDS` (`scooter`, модель `createScooter` в `src/models/race-cars.js`). Он стоит в мире, пока выполняется условие, — это данные квеста: `world.vehicles: [{ kind, at, dx, dz, heading, if }]`
(`src/quests/world.js`); сесть без ключей, бензина хватает надолго (`economy`). Условие `driving:scooter` — герой именно за рулем этого вида (в сценарии: `{ drive: 'scooter' }`).

### Подсказки к квесту: направление, подсветка, двери

Вкладка настроек «Игра» (`src/engine/settings.js`) — три настройки: «Вид от первого лица» (`firstPerson`, выключена: камера в глазах героя в бою и в салоне машины за рулем) и две подсказки, обе включены: «Показывать направление» (`showPath`) и «Подсвечивать объекты» (`showObjects`), код — `src/quests/guide.js`.
**Направление:** от героя до цели текущего шага идут небольшие зеленые стрелки прямо по земле, та же линия со стрелками лежит на миникарте и большой карте. Путь ищет A* (клетка 3 юнита, по кадрам, чтобы не подвисало) и нарочно не самый короткий, а простой и предсказуемый:
здания, река, кусты и деревья не проходятся; дорога, улица, тротуар и тропинка в разы дешевле травы и леса, поэтому путь держится их; рядом со стеной штраф, за каждый поворот штраф (чем резче, тем больше), поэтому он идет длинными прямыми, а не лесенкой;
потом точки упрощаются до поворотов (отрезок не срезает дорогу по траве и не жмется к препятствиям) и слегка скругляются. Он пересчитывается при смене цели и когда герой ушел с пути; внутри зданий стрелок нет.
**Объекты:** то, к чему нужно подойти (человек у места, вход в здание, вещь из условия шага `has:вещь`, само место), помечено покачивающимся ромбом с кольцом, как ромб над вашей машиной.
**Двери:** когда на дверь, лестницу или кнопку, которыми можно воспользоваться сейчас, наведена мышь, сам объект чуть ярчает (светлее и теплее, плавно туда и обратно), а сканер подписывает его («Вход в гараж»).
Пока так сделано для входа в гараж, кнопки гаража и лестницы дома (у них есть сетки: `glowMeshes()`); остальные входы подсветим по тому же образцу (запасная плашка отключена: `DOOR_FALLBACK_PANELS`). Запись `interactables` задает `glowMeshes()`, `glowAt()`, `doorName`, `clickPoint()`.
Клик по топливной колонке заправляет машину, если она стоит у колонки (за рулем или рядом пешком), как E (`src/locations/city/gas-station.js`). Клик по двери считается и по ее положению на экране (дверь вертикальная, луч по ней попадает в землю за ней).
**Гараж:** кнопка двери при открытии вдавливается и зеленеет; когда герой побывал в гараже, вышел или выехал и отошел от проема, дверь сама закрывается, и кнопка отжимается (`updateGarageAutoClose`, `src/player/home.js`).

### Заречье: домик Веры далеко в лесу

Домик на дереве стоит далеко за домом Анны Петровны: за оврагом (через бревно) начинается извилистая тропинка по лесу (~250 юнитов, кривая через опорные точки в `src/locations/zarechye/grandma.js`),
она приводит на поляну с огромным деревом, вокруг которой стеной стоят густые высокие деревья. Сам домик виден, только когда подошел ближе 30 юнитов, издали его закрывает листва. Тропинка — «дорога» для карты и поиска пути (`mapRoads`),
бревно задано как мостик поиска пути (`navLinks`). Из-за дальней дороги пешком таймеры шагов «вернуться в домик» увеличены (2.05, 2.11, 3.04, 3.06, 5.02).
Овраг с ручьем вырыт ниже земли (в земле для него прогал, `ravineGap` в `src/locations/shared/coords.js`; откосы, дно и ручей — меши в `grandma.js`), а бревно через него низкое: верх чуть выше земли (0,28), герой идет по нему, а не сквозь него (высота земли под бревном — `groundExtras`, `src/engine/helpers.js`).
Подсветка объектов (настройка «Подсвечивать объекты») теперь отмечает и то, на что нацелено действие активного квеста (`interactions`): ноутбук Веры, верстак, горн и т. п.; станции зданий и объекты мира отдают свои положения (`stationId`, `questSpots`).

### Супер-предметы: окно с подробным рассказом

Телефон, рюкзак, браслет, прибор тканей, погодный прибор, артефакт и любое оружие — супер-предметы (даже телефон: сто лет назад никто не поверил бы, что в такой коробочке столько возможностей).
Время стоит и пока открыто меню настроек (Esc или O): игровые часы, люди, машины и таймеры квестов замирают (`gameFrozen`).
Когда герой получает такой предмет впервые, открывается окно на весь экран (`src/quests/supers-ui.js`): время останавливается (мир замирает, таймеры стоят), слева предмет нарисован очень крупно (пиксельный рисунок 32×32 с подсветкой и тенью),
справа подробно рассказано, что он умеет и как им пользоваться; закрыть — «Понятно», Enter, E, пробел или Esc. Показанное запоминается в сохранении (`state.supers`). Если при этом должен зазвонить телефон, сначала окно, потом звонок.
Тексты — данные: `defineSuper(id, { when, art, kicker, title, tagline, sections })` в `src/content/supers.js` (условие `when` как у квестов: `has:phone`, `flag:braceletCased`); запись `weapon` с `template: true` — образец для любого оружия
(название и описание берутся у самого оружия). Рисунки — функции в `SUPER_ART` (фигуры на сетке; свет, тень и контур добавляются сами); у предметов без рисунка — значок инвентаря вдвое крупнее.
Новый супер-предмет — запись `defineSuper` и, если нужен особый рисунок, функция в `SUPER_ART`.

### Интерфейс без подсказок

Игровое время идет как в обычном мире (`minutesPerSecond` = 1/60, `game.json`): справа сверху (левее кнопки «на весь экран») одна строка «18.09.2043 11:24:54», без погоды. Шрифт, размеры и вид всех панелей — в дизайн-системе (`docs/design-system.md`). Время тратится еще на перемещения и ожидание (`wait`, кнопки в телефоне).
Постоянных подсказок про управление нет (ни «клик по земле — идти», ни «E — действие», ни надписи в начале игры; вместо них — окна супер-предметов): подсказки у предметов («E — взять…») появляются после первого квеста, до него путь указывает телефон (`src/quests/gates.js`).
Кнопка «на весь экран» — значок без подписи. Сканер («что это») справа снизу маленький, нейтральный и виден, только пока курсор наведен на человека, здание, предмет или машину.
Снизу пока нет оружия видны лишь занятые ячейки (ключи), все восемь появляются с первым оружием. Герой не прыгает.
Клик по земле никуда не ведет: клик по входу в здание, лестнице, выходу, человеку или машине — герой полсекунды идет туда, и локация меняется сразу, а время уходит как на путь пешком даже издалека
(`clickDoorFrames`, `clickPoint()` у записей `interactables`, `src/player/click-move.js`).

### Эликсир: установка синтеза Веры (2.05) и парковка в Заречье

Эликсир не варят из воды и меда: его синтезирует установка Веры — большой серверный шкаф в северо-западном углу домика на дереве, у ствола (станция `synth`, `src/content/buildings/treehouse.js`;
светодиоды мигают, по бокам трубки охлаждения, кабели по полу). Это квантово-полярный вычислительный синтезатор: Вера собрала его по частям из блоков лаборатории по схеме из «теории» Максима (в подвале лаборатории таких установок множество, Ф46, открывается у потайного люка в 4.09).
Реагенты — вещества, которых еще нет в справочниках: квантово-полярный катализатор, тахионная пыль, антиспиновый гель, хроно-стабилизатор, кристалл-затравка (предмет `elixir_kit`; Людмила в торговом центре принимала их за запчасти). Головоломка 2.05 — порядок синтеза
(откачать воздух, охладить контур до нуля, тахионная пыль, катализатор, гель, запутать контур, хроно-стабилизатор, затравка). Верстак остался для остальных приборов (браслет, погодный прибор, артефакт).
### Заречье: отдельный поселок и парковка у дома

Заречье — поселок за кирпичным городом (`src/locations/zarechye/grandma.js`): от южной окраины города (x = 574) идет сельская дорога шириной 9 (`roadV` получила параметр ширины), через ~150 юнитов она упирается в улицу поселка (z = 230, ширина 10) с четырьмя домами соседей. Дом Анны Петровны (двухэтажный, 24 × 15, гараж 7,4 справа, определение `grandma_house` в `src/content/buildings/treehouse.js`: внизу гостиная и кухня, наверху комната Веры и спальня бабушки, лестница) стоит на южной стороне в глубине участка. Овраг сдвинут южнее (`ravineZ` = 304), домик на дереве, тропинка и бревно считаются от него.
Объездная дорога к домику Веры (`detourPts` в `grandma.js`): без знаков и подсказок, две колеи по траве. Начинается там, где кончается западный край улицы поселка, огибает участки с запада, переезжает овраг по земляной перемычке с трубой для ручья (`ravineCross` в `src/locations/shared/coords.js`: в земле и на овраге в этом месте разрыва нет) и сквозь лес выходит к поляне с южной стороны, то есть сзади огромного дерева, где есть разворотная площадка. Лес вдоль нее не растет, на карте она едва заметна. Так на машине можно доехать до домика, не ходя по тропинке через бревно; проходимость проверена по препятствиям и деревьям.
Парковка у дома, как в американских фильмах: подъездная дорожка к гаражу от улицы, на ней старая машина бабушки (закрыта) и свободное место для машины героя, место `zarechye.parking`; место `zarechye.road` (откуда стартуют телепорты квестов) — на улице напротив участка.

### Погода сюжета: прибор Веры

В обычных играх погода — настройки; здесь ею управляет супер-предмет. Режим погоды — состояние сюжета (`state.weatherMode`, действие `{ weather: режим }`, условие `weather:режим`),
показывает его `src/quests/weather-story.js` (обертки над `updateSchedule` и `updateRain` из `src/world/weather.js`; настройка «Всегда солнечно» сюжет не отменяет):

| Режим | Когда | Что |
|---|---|---|
| `gloom` | с начала игры, до прибора | хмуро: пасмурное небо, густой воздух, обычные дожди по расписанию |
| `storm` | со сговора о гонке (3.05, шаг `talk`) до утра на треке | ужасный ливень без остановки, темно, шины почти не держат (`weatherGripFactor` в `driving.js`: сцепление ×0,38) |
| `sun` | утро гонки на треке (3.05, шаг `morning`) | прибор разогнал тучи, ясное солнце |
| `auto` | после гонки (3.05, шаг `win`) | всегда солнечно; изредка начинается дождь, герой: «Надоел этот дождь!», прибор сам разгоняет тучи, тратит до 25 эликсира: «Так то лучше!» |
| `rain` | нашествие роботов (3.13), кнопка «Вызвать ливень» в телефоне | призванный ливень: роботы коротят (40 урона током каждые полсекунды), пули их почти не берут |
| `fog` | 5.02 (люди в черном ищут героя и Веру), кнопка «Навести туман» | густой туман на весь город |

В квестах с призванным ливнем и туманом случайных дождей нет. Прибор — предмет `weather`: его собирают в 3.06 «Погода по заказу» (параллельно 3.05: гонка не начнется, пока прибор не собран; головоломка на верстаке в домике на дереве, 20 эликсира).
Цепочка теперь: … 3.04 → 3.05 (+3.06) → 3.12 → 3.13 → 4.09 → 4.12 → 4.11 → 5.02.

### Трасса от поселка до города

Дорога от дома героя до моста — сельская: потертое светло-серое полотно, колея, пара светлых заплаток, пятна гравия, грунтовая обочина и трава по краям, осевая бледная и редкая (`src/world/highway.js`). Почти вся она прямая вдоль z = 0, потому что к прямой привязаны заправки (x −1110, −700, −290, −140), съезды на трек (−620) и в лабораторию (−330), торговый центр и города. Два участка вьются плавными дугами радиусом ≥ 55 и идут по пологим холмам (до 4 юнитов, уклон до 0,065): x −1076…−736 и −590…−342 (`highwaySections`, `src/world/highway-path.js`). На них полотно широкое (полуширина 7,5: две полосы и запас), так что на скорости 0,8 можно входить в поворот заносом; у заграждений погони 2.12 оно сужается до обычного (шиканы рассчитаны на него), а сами заграждения стоят там, где дорога параллельна оси X и на земле (`highwayChaseXs`, места `chase.b1…5`). Кусты вдоль дороги — упругие препятствия, как бочки на трассах (`bouncy`), стоят за обочиной, в 9–10 юнитах от оси на кривой, и по полотну их не задеть.
Длина пути от дома героя до моста — `highwayLengthToRiver` (**1724**); на обычной машине (макс. скорость 0,8, разгон до 100 км/ч за 10 с) без ошибок это **около 44 секунд** реального времени. Бензин и таймеры квестов считаются по этой длине: прямая (z = 0) — 1641.

### Отдельные локации (страницы)

Чтобы большой мир и память браузера не раздувались, места, где идет отдельное действие, — **отдельные страницы со своим небольшим круглым миром**:
`locations/track.html` (гоночный трек), `locations/lab.html` (лаборатория), `locations/tower.html` (девять этажей башни). Остальное — основной мир
(`index.html`): трасса, города, Заречье, торговый центр, башня снаружи с вертолетиком, а к треку и лаборатории от трассы уходят дороги со
знаком и шлагбаумом (`src/locations/entrances/entrances.js`). Страницы локаций собирает `node tools/build-locations.js` из `index.html`
(блок между `<!-- world:begin -->` и `<!-- world:end -->` заменяется миром локации); тест `tests/locations.test.js` проверяет, что они не устарели.
У места (`definePlace`) есть `location` (по умолчанию `main`): на чужой странице расстояния до него нет, спутники и враги там не появляются, а
`marker` шага может быть своим на каждой странице: `marker: { main: 'track.entrance', track: 'track.start' }`.
Переход между страницами — действие `{ teleport: 'место' }` (если место в другой локации) или переход-данные `definePortal({ id, at, to, heading })`: состояние
игры (как сохранение: положение, машина, вещи, время, ход истории) кладется в sessionStorage и принимается на новой странице (`src/quests/transit.js`);
сохранение слота помнит, в какой локации сделано, и загрузка сначала переходит на ее страницу. Координаты общие — `src/locations/shared/coords.js`.

### Гонка, тренировка и подарок-машина

Квест 3.12 «Яхта Барона»: Барон приплыл на яхте, по ночам в городе происшествия (`spot:inc1/inc2`, два улика-диалога), вечером (`time` 19:00–23:59 + `near` у яхты; журнальная кнопка «ждать до 19:00» = `waitUntil`) на берегу бой с киборгами и дроном (`fights.yacht`, две волны), с обломков (`spot:wreck`) игрок берет микросхемы (предмет `chips`) и читает серийные номера и накладную (Ф42, Ф43: серии лаборатории Штерна, поставки Барону). Микросхемы пока только предмет: сборка «суперустройств» (`meta.todo.chips`) — позже.

Квест 3.05 «Крутая тачка»: контрольные точки — данные квеста (`checkpoints: { counter, order, when, driving }`, `src/core/game.js`): пока
`when` истинно, герой за рулем проезжает места по порядку, счетчик растет. Кнопки квеста (`actions: [{ id, text, if, do }]`) видны в
журнале (J) и запускают действия по желанию игрока: «Потренироваться вечером» открывает выбор машины (`src/quests/practice.js`), переносит
героя на трек и ставит вечер, а браслет (кнопка внизу или B, действие `{ practiceEnd: true }`) возвращает положение, машину и игровое время.
`{ markDay: 'deal' }` и условие `dayssince:deal>=1` — «на следующее утро» (сутки считаются по полуночи). `{ playerCar: 'hyper' }` дарит
герою машину из `VEHICLE_KINDS` вместо его (запоминается в сохранении), `{ breakCar }` и `{ repairCar }` делают машину хромающей и чинят,
`{ kill: true }` «убивает» героя после неудачной погони, а `rewind` и `repeat` дают новую попытку. Трек — `src/locations/track/track.js`.
Машины мира (`src/models/vehicles.js`, `race-cars.js`, `src/world/vehicles.js`) теперь подключены и в основной игре.

### Радиоуправляемый вертолетик

Действие `{ heli: { from, goal, goalY, goalR, onGoal } }` (`src/quests/heli.js`) запускает вертолетик с места `from`: W/S, A/D, Пробел и Shift
(выше и ниже), E у цели выполняет `onGoal`, Esc убирает его. Герой на время полета спрятан и неуязвим, камера идет за высотой. В квесте 4.12
он нужен, чтобы долететь до крыши башни, где бомба (десятый этаж заперт). Высокие объекты мира могут иметь `fade: true`,
чтобы не заслонять героя от камеры.

### Бои

Бой — данные в файле квеста (`fights: { flash: { when, foes, onWin } }`, `src/core/fights.js`): враги стоят, пока истинно `when`,
волны (`wave`) выходят по очереди, победа — условие `fight:2.11.flash` и действия `onWin`. Враги — виды `cyborg`, `hound`,
`cain`, `drone`, `stilt` (`src/quests/fights.js`, упрощенные существа ДЕМО на боевой платформе). Бои идут на улице:
в зданиях врагов нет, поэтому «подвал» лаборатории (`src/locations/lab/lab.js`) — открытая площадка с высокими стенами.
Новые действия: `{ wait: '8h' }` (время), `{ teleport: 'место' }`, `{ heal: 40 }`, `{ elixir: -20 }`; условие `elixir:>=20`.

### Мир из данных

Люди и предметы местности — записи содержания, код под каждый не нужен (`src/quests/world.js`): персонаж с `at: 'место'`
(`defineCharacter`) стоит там всегда, `world.people` в квесте — только пока выполняется `if`, `defineSpot` ставит на
улице объект из боксов, E рядом отдает взаимодействие квесту (`on: 'spot:forge'`). Места задаются в `src/quests/places.js`.
Слесарная мастерская, автомастерская и заправка пока стоят во дворе у заправки на трассе, вместо Каменки и города. Объекты могут быть
твердыми (`solid: true`) или без взаимодействия (`noInteract: true`).

### Что упрощено в цепочке

Погоня 2.11 — засада у дерева без езды на машине; 4.08–4.10 сжаты в 4.09, лаборатория — открытая территория без зданий; в 5.02
время не откатывается, а Вера не дерется, а лечит. Все это — места для следующих итераций (`meta` у квестов).

## Что растет потом

Каждый шаг делается, когда предыдущий уже играется целиком:

1. **Удлинение основной линии**: новые квесты в середине цепочки (остальные квесты сюжета). Формат тот же,
   меняется только `next`.
2. **Побочные квесты**, которые можно не выполнять: `optional`, шаблоны `defineQuestTemplate`, `roles`.
3. **Таймеры, поражение вертолетом, мир квеста** (`world`: объекты, живущие пока квест активен).
4. **Развилки и исходы** (`outcomes`, выборы с последствиями), игра за других героев (например за Веру).

Всё это расширяет формат квеста новыми необязательными полями; квесты v1 продолжают работать без правок.

### Слесарная мастерская и сон

Михалыч — слесарь, а не кузнец: его мастерская во дворе у заправки — современная металлообработка (токарный станок, фрезерный станок с ЧПУ, верстак с тисками, инструментальный шкаф, стеллаж со сталью; в коде это объект `forge` в `src/content/world.js`, id остался от прежней кузницы).
Головоломки «ритм» у него — подача на станке (`bellows` в данных квестов 2.08, 2.13, 3.04; название «Станок»). Корпус делают быстро, в тот же день: ждать до завтра не нужно.
Чтобы попасть в следующее утро, где игре нужен новый день: кровать на втором этаже дома или гамак в домике на дереве (E: лечь спать до 7:00), а в заданиях, которые ждут времени суток (вечер у яхты, утро гонки), — кнопки в телефоне («Задания»).

### Машина героя

Это черная Nissan Almera Classic (B10, 2006–2011), номер «ДЕТ 001»: в модели `createCar` (`src/models/car.js`) стиль `almera` — седан из выдавленного бокового профиля (капот, крутое лобовое, высокая крыша, короткое заднее стекло, высокая палуба багажника),
боковые и лобовое стекла, решетка с хромированной планкой и логотипом, большие фары и фонари заднего вида, туманки, зеркала и ручки; контур светлее обычного, чтобы черный кузов читался. Размеры для столкновений прежние. Ромб над машиной остался бирюзовым (цвет «ваша машина»).
